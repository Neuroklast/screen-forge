# Exercise Preparation Checklist

> ScreenForge · One-page trainer checklist · Language: EN, UI labels DE
> Concept: [../konzept/scenarios/12-safety-profile.md](../konzept/scenarios/12-safety-profile.md) · [../konzept/scenarios/00-realism-and-safety-framework.md](../konzept/scenarios/00-realism-and-safety-framework.md)

## Before setup

- [ ] Training goal written in one sentence; no decorative injects without a purpose.
- [ ] Scenario: every MEL row has trigger, effect, expected outcome and fallback.
- [ ] References: only officially released or deliberately fictional content; no leaked SOPs/TTPs.
- [ ] Devices: stations match roles; all bindings validated.

## Safety

- [ ] Safety officer named; abort tested; stop signal known to everyone.
- [ ] Props registered, inert, and clearly distinct from real material.
- [ ] Imitation weapons: transport, area, public exposure and local law checked (§ 42a WaffG).
- [ ] Pyrotechnics: no improvised effects; external specialist responsibility if used at all.
- [ ] Medical: moulage/simulation unambiguous; real medical help separate from the exercise.

## Readiness

- [ ] Devices online, correct role, correct mission, sufficient battery, permissions checked.
- [ ] Offline: at least one full disconnect/reconnect tested.
- [ ] Time: all countdowns derive from the exercise clock/server time, not standalone browser timers.
- [ ] Briefing: role knowledge and forbidden knowledge separated; stop signal known.

## During

- [ ] MSEL linter clean; baseline snapshot stored.
- [ ] Controller steers only injects; safety steers only safety; assessor observes and changes nothing.
- [ ] On deviation: use hold, skip, fallback or branch — do not invent hidden rules.
- [ ] On danger: real safety overrides the simulation immediately — abort.

## After

- [ ] Exercise end shown explicitly on all devices.
- [ ] AAR discusses concrete log events, not recollection.
- [ ] Follow-up: inject result, unexpected behaviour and proposed scenario change documented separately.
